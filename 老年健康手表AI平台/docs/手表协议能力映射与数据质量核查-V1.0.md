## 3. 二进制帧与解码

外层帧结构：

~~~text
[15 字节 deviceid]
[magic(2) | len(2 LE) | crc(2) | opt(2 LE) | payload(len)] × N
~~~

| 字段 | 含义 | 风险 |
|---|---|---|
| deviceid | 15 字节 ASCII 设备号 | 需与绑定关系核对 |
| magic | 固定 0x44 0x54 | 非法帧拒绝 |
| len | uint16 小端，payload 长度 | 检查越界、截断和多帧拼接 |
| crc | payload CRC | CRC 算法细节未在官方文档完整说明 |
| opt | 0x80、0x0A、0x12 等类型 | 决定 Protobuf 消息类型 |
| payload | Protobuf 序列化内容 | 依赖官方 .proto 版本 |

重要约束：

- 一个 HTTP 请求可能包含多个子包。
- 二进制 body 的真实内容是 application/octet-stream，但 HTTP Header 的 Content-Type 可能声明为 application/x-www-form-urlencoded。
- 服务端必须读取 raw body，不能用表单解析器处理。
- 成功应答字节为 0x00；失败应答和重传语义需要与厂商确认。
- 应答时机要确保原始报文已经可靠归档或进入持久化队列，避免返回成功后数据丢失。

## 6. 厂商算法调用契约

| 算法 | 输入准备 | 重要约束 | 输出/存储 |
|---|---|---|---|
| 睡眠 | 当天/前一天 sleep string + RRI | 必须有两天数据；跨零点；E 来自 sleep_raw | sleep_daily、sleep_segment |
| 心电 | 单次 ECG 采样点 | 同一 time_stamp 分片合并；保留采样顺序 | algo_result(kind=ecg) |
| 房颤 | 当天全部 RRI | 少于 10 点不调用；不额外换算单位 | algo_result(kind=af) |
| 血氧 | 连续 SpO₂ | 只取实际睡眠 start_time 到 end_time 窗口 | algo_result(kind=spo2) |
| 长程心电 | 多导联文件 | ≥1 小时、≤72 小时、≤100MB；异步回调 | ecg_report |

算法接口公共约定：

- 请求凭证与设备指令鉴权方式不同，必须分开实现。
- 成功结果字段大小写应按可运行官方示例解析。
- 非 0 ReturnCode 不落成功结论。
- 算法服务失败不阻塞其他任务，进入重试队列。
- 记录输入数据版本、请求摘要、算法版本和原始响应。

## 7. 下行指令实施分组

| 类别 | 指令 | 风险控制 |
|---|---|---|
| 用户/设备初始化 | userinfo、language、timeformat、dateformat、wearhand | 初始化配置校验 |
| 数据上传 | datafreq、locate_freq、datasync | 关注流量、功耗和补传 |
| 测量频率 | measure_hr、measure_other | 关注续航与采样完整性 |
| 心率/血氧/血压/体温告警 | hr_alarm、hr_alarm_dynamic、spo2_alarm、bp_alarm、temp_alarm | 需经审核的阈值配置 |
| 其他生理告警 | sugar_alarm、potassium_alarm、autoaf | 字段来源/单位未确认前不启用 |
| 跌倒/久坐 | fallcheck、fallcheck_sensitivity、sedentary | 跌倒灵敏度变更需记录 |
| 血压计划 | bp_schedule、bp_adjust | 校准参数需专业审核 |
| SOS/通讯录 | phonebook_sync、phonebook_clear | 需要家属授权与二次确认 |
| 定位 | realtime_location、gps_locate | 位置权限与隐私控制 |
| 不可逆操作 | factory_reset | 二次确认、审计、禁止自动触发 |

下发后使用 device_setting 保存期望配置和状态：

- pending：已创建任务，等待发送；
- sent：请求已发出；
- accepted：服务端返回接受；
- confirmed：有设备端确认依据；
- failed：失败，保留错误码；
- unknown：无法确认是否真正生效。

若协议没有设备端确认机制，不得把 accepted 显示成 confirmed。

## 9. 数据上线准入规则

字段只有同时满足以下条件，才允许进入风险引擎：

1. 已确认字段含义和数据来源；
2. 已确认单位、量纲和换算；
3. 已确认时间戳及采样窗口；
4. 已确认有效值范围和无效标记；
5. 已通过真实设备样本解码测试；
6. 已有质量检查和异常处理；
7. 风险规则有适用人群、依据和审核记录。

仅仅“协议中存在字段”不代表“产品可以安全使用该字段”。
